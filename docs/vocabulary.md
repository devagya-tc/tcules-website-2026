# The Tcules token vocabulary

**Every colour, distance, type role, glyph and prop union this design system actually has.** It is
generated out of the repository's token layer, so a name here is a name that resolves in the browser.

Use it when you are **specifying a new component**: the hex values are exact and are given so you
can compute WCAG contrast ratios and state a measured number in the spec. You will not need it to
*compose* a mockup out of the Tcules component library — those components are already correct on
every surface.

**Never write a token name that is not in this document.** A plausible-but-wrong name — 800 where
you meant 700 — renders perfectly and is wrong forever, and no build check can catch it. When a
value genuinely does not exist, raise a NEW TOKEN REQUEST instead.

### MONO IS ALWAYS UPPERCASE — and uppercase in presentation ONLY

Mono is this system's label voice: chrome, eyebrows, keys, control labels, stats. All
10 mono roles are cut for capitals — their tracking is opened 0.08–0.12em, which is a
correction for the side bearings of capitals — so set lower-case, a mono role reads as
letter-spaced body text rather than as a label. **The case belongs to the role, not to the
component.** 9 of the 10 take it: `--text-ui-sm`, `--text-ui`, `--text-ui-lg`, `--text-eyebrow`, `--text-index`, `--text-micro`, `--text-stat`, `--text-stat-lg`, `--text-stat-xl`.

Write it beside the font, exactly as you write tracking, and for the same reason — `font:` carries
a family, weight, size and ratio, and no transform:

```css
font: var(--text-eyebrow);
letter-spacing: var(--text-eyebrow-tracking);
text-transform: var(--text-mono-case);
```

**In presentation only.** Never write the uppercase into the copy, a prop, a CMS field or an
`aria-label`: pass "Read more", not "READ MORE". The string stays in the capitalisation somebody
authored, which is what a screen reader announces and what an editor edits; the sheet does the
shouting. One token, so the whole decision reverses in one declaration.

**A label that must stay sentence case is not a mono label** — give it a sans role. That is the
resolution, not an exemption: mono has exactly 1, `--text-code`, where mono is
**content** rather than a label and case is semantic — `Section` and `SECTION` are different
identifiers. Numerals have no case, so the transform is a no-op on a stat's digits and normalises an
alphabetic suffix: "12k" sets as "12K".

### Titles balance, running text wraps pretty

Wrap is a property of the role, like case, and it has two answers. **Every title role** (display,
h1–h6) is balanced, so a long title breaks into near-equal lines instead of leaving one word on the
last. **Running text** — lead, body-lg, body, body-sm and quote, wherever they set sentences — wraps
pretty: every line keeps the measure and only a closing single word is avoided. A UI line that
borrows a body size (a nav row, a field label, a crumb) takes neither, and neither do mono labels.

```css
font: var(--text-h2);
letter-spacing: var(--text-h2-tracking);
text-wrap: var(--text-title-wrap);
```

Two tokens, one per decision: `--text-title-wrap` and `--text-running-wrap`. Design titles
against their longest real copy — a ten-word h1 or h2, an eight-word card title — not a four-word
placeholder that never wraps.

### The three layout primitives — their real prop APIs

Layout is done by these three. Always. Anything you specify is arranged by one of them.

**`Section`** — `as?: ElementType` · `surface?: SectionSurface` · `density?: SectionDensity` · `flush?: boolean` · `children: ReactNode` · `'aria-labelledby'?: string` · `'aria-label'?: string` · `'data-band'?: string` · `'data-fold-hero'?: ''` · `'data-arrangement'?: string`

  where `SectionSurface` = 'paper' | 'tint' | 'ink' | 'blue' · `SectionDensity` = 'strip'

**`Layout`** — `as?: ElementType` · `rowGap?: Gap` · `colGap?: Gap` · `columns?: Columns` · `minTrack?: MinTrack` · `equalRows?: boolean` · `lead?: boolean | 'tall'` · `reverse?: Responsive<boolean>` · `offset?: Responsive<Offset>` · `pinLast?: boolean` · `fillFirst?: boolean` · `stagger?: boolean` · `align?: Place | 'baseline' | 'first-baseline'` · `justifyItems?: Place` · `justify?: Distribute` · `scroll?: Scroll` · `peek?: boolean` · `ref?: Ref<HTMLElement>` · `tabIndex?: 0 | -1` · `'aria-label'?: string` · `children: ReactNode`

  where `Gap` = 'none' | 'inline' | 'tight' | 'text' | 'block' | 'gutter' | 'stack' | 'column' | 'section' | 'section-open' · `Columns` = (number | (number | 'auto')[]) | 'fit' | 'tile' | { base?: ColumnSpec; md?: ColumnSpec; lg?: ColumnSpec; xl?: ColumnSpec } · `MinTrack` = 'xs' | 'sm' | 'md' | 'lg' · `Offset` = 0 | 1 | 2 | 3 · `Place` = 'stretch' | 'start' | 'center' | 'end' · `Distribute` = 'start' | 'center' | 'end' | 'between' · `Scroll` = 'until-md' | 'always'

**`Cluster`** — `as?: ElementType` · `rowGap?: ClusterGap` · `colGap?: ClusterGap` · `align?: ClusterAlign` · `justify?: ClusterJustify | { base?: ClusterJustify` · `nowrap?: boolean` · `stackUntil?: 'md'` · `children: ReactNode`

  where `ClusterGap` = 'inline' | 'tight' | 'text' | 'block' | 'gutter' | 'stack' · `ClusterAlign` = 'start' | 'center' | 'end' | 'baseline' | 'stretch' · `ClusterJustify` = 'start' | 'center' | 'end' | 'between'

Read the unions above literally: a key that is not in them does not exist. `rowGap` and `colGap`
take **gap-scale role names**, and neither has a default — an axis nobody states renders 0, on
purpose. State `colGap` only where you also set `columns`; a single-track stack has no column
seam to size.
